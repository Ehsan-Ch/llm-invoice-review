The included SQLite queue starts every invoice as pending. Approval rechecks the source and arithmetic. Decisions require a reviewer label, reason, and current record version; every transition is logged.
These controls are available through the command-line application. This report only inspects saved results. No approval is made by this page, and the project never initiates payments.
Repeated identical text is deduplicated. This is not business-level duplicate-invoice detection. Reviewer names are local labels, not authenticated identities.


What this experiment can establish
The Qwen3-0.6B Q8_0 model ran locally through llama.cpp. It receives invoice text and returns values with exact supporting lines. Validation checks the field label, quoted line, copied value, currency, date order, and subtotal + tax = total using decimal arithmetic.
Optional correction changes a value only when its cited line is exact, uses a recognized field label, and the source has one unique value for that field. Missing or conflicting evidence is not repaired. Original model output and every correction remain visible.
Supported inputs are short text invoices with explicit labeled fields, ISO dates, DKK/EUR/USD, and supported unsigned amount formats. There is no PDF/OCR ingestion, line-item accounting, discount/credit handling, tax compliance check, fraud detection, or production security boundary. The small synthetic sample does not demonstrate performance on real invoices.
